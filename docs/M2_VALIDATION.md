## 实际交付

| 范围       | 实现                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 模型连接   | 对话和向量独立配置/测试，后端解密，30 秒单请求超时，禁止重定向，响应体上限 8 MiB，限流/部分服务错误最多 3 次退避尝试                |
| 结构化分析 | 直接回答概念是什么，给出简明定义及可选短例子；结构校验失败最多尝试 2 次；不覆盖正文                                                 |
| 检索       | 按标题/行切分正文，保留 hash、行号、正文版本；pgvector 精确余弦距离与中文分词/二字片段融合，最多 10 候选，附带最多 5 条已有关系背景 |
| 建议       | 最多 5 条，解释匹配程度与疑似重复；目标必须属于召回集，两端引用必须逐字存在于草稿和候选片段                                         |
| 审阅       | 逐条接受/拒绝，可改类型、方向和说明，手工补充目标；决定有独立版本，保存后刷新可恢复                                                 |
| 持久工作流 | LangGraph parse → match → suggest → interrupt(review) → commit，PostgreSQL 检查点；pg-boss 独立 worker 调度，同一 run/thread 恢复   |
| 正式写入   | 明确确认后复用 M1 原子提交；草稿和目标版本复核，固定提交操作 ID，确认/解析/候选/建议快照保存，outbox 和结果节点在同一事务写入       |
| 失败和取消 | 失败可从检查点重试，成功步骤缓存；正文改变使旧分析失效，模型配置变化需重分析；取消中的请求会停止或在后续检查点终止，不入图          |
| 调用记录   | 记录实际请求尝试、耗时和服务实际返回的 token 用量；缺失用量保留缺失，不生成价格或接受率估计                                         |

## 当前限制与后续

1. 真实模型服务未配置，兼容协议与建议质量尚未验收。HTTP 协议测试通过不代表所有兼容厂商都支持相同参数或结构化输出能力。
2. 引用校验保证片段存在，不证明模型解释或关系正确。最终关系仍需用户审阅；模型建议不会自动接受。
3. 进度采用 1.5 秒轮询，SSE 未接入；云图临时虚线候选预览留到 M4，自动云团与算法配色留到 M5。
4. 未保存的审阅表单是当前页面状态；点击保存后持久化。修改草稿标题、正文或别名后需重新分析，AI 不直接改原文。
5. 单次 AI 草稿分析最多 6 万字符。已有内容初次建索引可能较慢并产生模型费用；旧版本向量缓存暂不自动回收，后续补缓存清理策略。
6. 配置指纹涵盖服务地址、模型 ID、用途和加密凭据，维度变化会拒绝混算；无法检测服务端在相同模型 ID、相同维度下暗中替换权重。更换模型应使用新配置或模型 ID。
7. M2 最终验收仍需：配置真实对话及向量模型、完成 50 条真实工作流评估、用户复核标签与典型误判、确认检索门槛和建议方向质量。

验收过程中 Docker 虚拟磁盘空间用尽。已仅删除本次开发的闲置旧镜像和经核实的本项目构建缓存，未删除数据卷或其他项目镜像。还定位并修正了 pg-pool 结束与测试库强制删除的时序竞争：清理脚本等待会话退出后再删除，最终回归退出码为 0。

## 2026-10-28 百炼向量接入修复

实际录入任务在 `match` 阶段第一次 `query-embedding` 请求返回 HTTP 404；此前对话解析已成功。向量配置使用了 Token Plan 专属接口及专属凭据，而非百炼通用向量服务。本次错误发生在首个请求，不能归因于批量上限。

另修正了后续可能触发的批量兼容问题：模型网关统一将向量输入拆成最多 10 条一批，显式请求 float 输出；每批索引从零开始，合并后保留原输入顺序，并检查跨批维度一致性。这样检索层 24 条的调度单元不会直接变成 24 条的供应商请求。404 和 401/403 会给出向量接口及密钥配对提示，不返回供应商原始错误或凭据。

新增 4 项回归：24 条拆成 10/10/4 且乱序响应正确归位、跨批维度变化拒绝、Token Plan 向量 404 提示、密钥鉴权错误提示。`npm run check` 共 7 项测试通过，构建通过。

向量配置修改后旧运行的模型版本已不同，应从草稿重新开始分析。实际向量连通与整条录入仍需用户在产品中保存百炼通用 API Key 后验证；未自动改写现有凭据或替用户确认入图。

参考：[百炼向量接口与批量限制](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api/)、[密钥及接口地址配对说明](https://help.aliyun.com/zh/model-studio/error-code)。

## 2026-10-28 概念解释简化

按用户反馈，将录入第一步改成直接回答“这个概念是什么？请用简单的方式介绍它的概念”。模型输出只保留概念名称和简明解释，不再要求生成主题、歧义和拆分清单。UI 改为「概念解释」，移除待澄清、拆分建议及解析元数据编辑项；知识点标题和别名仍可在草稿自身编辑。

保留内部 `summary` 字段以兼容此前运行记录，新的运行会生成概念定义。原有审阅记录不会因部署自动改写；重新生成使用新运行与新提示词，仍需人工确认入图。

## 2026-10-28 划词流式解释

新增全局划词操作框和解释弹窗，支持正文预览、CodeMirror 编辑区与普通文本输入选区。点击 AI 图标后，以原样问题「xxx是什么？请以最简单的方式介绍它的概念」调用已保存的对话模型；单纯选择文字不发起模型请求，API Key 不进入浏览器。支持模型选择、停止、重新解释、关闭及 Esc。

`POST /api/explanations` 校验最多 500 字符及对话模型用途，后端对接供应商 SSE，按 delta 直接传给浏览器；共享解析器处理跨字节 UTF-8、CRLF 和分片事件。不采用完整生成后逐字播放。关闭/停止向上游传递取消，断流和失败保留已收到的部分文字并提示重试，缺少模型时提示配置。解释不写入知识点，只记录实际模型调用计量。

新增流式单元检查覆盖字节边界、截断、原样提示词、首段提前到达、思考字段忽略和实际用量。浏览器验证了选区按钮、输入框选区、分段显示、停止后上游连接关闭、Esc、重开和既有审阅入图流程。截图位于 `artifacts/word-explanation.png`。录入进度仍使用轮询，新增 SSE 仅用于这个解释功能。

协议依据：[百炼流式输出](https://help.aliyun.com/zh/model-studio/stream)。

真实本机验证也已通过：选中「知识空间」后调用已保存的对话模型，收到 252 字符回复，浏览器记录到 27 次增量文字更新，无页面异常。证据为 `artifacts/word-explanation-live.json` 和 `artifacts/word-explanation-live.png`。解释支持安全 Markdown 排版，原始 HTML 不执行。最终构建、12 项单元检查和 4 个浏览器用例通过。
