## 实现约定

- 模型协议首版采用兼容 `/chat/completions` 与 `/embeddings` 的 HTTP JSON 接口，Base URL 在模型设置中保存；对话与向量配置分别选择。连接测试验证真正的生成/向量响应，不只验证端口可连接。
- LangGraph 使用已有锁定版本和 PostgreSQL 检查点；业务运行表与框架检查点分开。工作流节点的成功结果缓存，确认事务以运行固定操作 ID 幂等提交。
- 任务由独立 worker 执行，页面只发起任务、查询进度和提交决定；待人工确认不占用持续模型调用。恢复与重复调度使用同一运行 ID。
- 语义索引按已保存模型配置版本、正文版本和分段 hash 缓存，使用 pgvector 精确检索；中文关键词独立召回，不能把内容相似度直接当连线依据。
- 结构化输出必须校验，建议必须引用实际召回端点和原文片段；最多 5 条建议。无依据输出失败后可重试，不放宽到自动确认。
- 初次语义分析可能需要为已有知识生成向量，界面说明并显示进度。正文仍可保存 100 万字符，首版单次 AI 草稿分析限制 6 万字符，超出时提示精简或人工录入。
- 草稿或候选版本变化后旧确认无效；修改标题、正文或别名后需重新分析。人工改关联不必重新请求模型。
- 运行记录和模型调用统计不保存 API Key；普通备份继续导出知识和确认来源，向量缓存与未完成运行可重建，不把运行凭据塞入备份。
- 前端先采用轮询进度接口，任务和人工暂停均持久化；后续需要更高频进度再增加 SSE。

## 验收重点

1. 空库、无匹配、全部拒绝都能明确确认独立入图；疑似重复必须再次明确选择独立新增。
2. 待确认刷新及应用/worker 重启后保留解析、候选、人工决定；没有新确认不得入图。
3. 草稿修改、端点改名/修改/删除导致旧决定不能提交；重新分析后才能继续。
4. 模型超时、限流、非法 JSON、伪造端点、错误维度、无依据引用均显示失败，草稿保留。
5. 取消请求终止模型调用或在下一检查点停止；取消与确认竞争时以数据库事务决定最终状态。
6. 入图中途失败整体回滚；提交成功后检查点落后、队列重复投递仍只有一个节点和一组已确认关系。
7. 可控 HTTP 模型用于回归；真实服务的检索质量、建议误判、接受率和耗时另行记录，不虚构真实模型验收。

## 当前外部依赖

本机知识库尚无模型配置。已向用户询问实际服务地址和模型 ID；API Key 应在产品设置中录入。开发、协议联调和隔离回归继续进行；真实模型质量验收等待可用的对话和向量服务。
