## 验证一 工作流持久化与业务幂等

**结果：通过。**

使用 LangGraph 1.5.3 与 PostgreSQL checkpoint 适配器 1.1.2。运行 ID 为 `m0-1d8f8bc7-37ad-4121-927c-be444c493ce1`，原始结果在本机 `artifacts/workflow.json`。

| 场景                             | 观察结果                                         |
| -------------------------------- | ------------------------------------------------ |
| 开始后等待人工确认               | 检查点保存 review 中断，正式验证记录数为 0       |
| 新进程恢复并确认                 | 确认通过后执行数据库事务                         |
| 数据库提交后、工作流检查点前退出 | 子进程以 86 退出，验证记录和 outbox 各有 1 条    |
| 再次启动新进程恢复               | 未完成的提交节点重放，返回已经保存的同一 node_id |
| 已结束线程再次执行               | 保持相同结果，无重复记录                         |
| 8 次并发提交相同操作             | 返回同一 node_id，记录与 outbox 各保留 1 条      |
| 同一操作 ID 携带不同内容         | 拒绝提交，事务回滚                               |
| 用户拒绝确认                     | 流程结束，没有写入验证节点                       |

确认结果使用 `{ approved: boolean }` 的结构化对象。业务写入放在独立节点，以唯一操作 ID 和事务保证幂等，不依赖 LangGraph 保证外部副作用只执行一次。M0 只建立 `m0.workflow_commits` 和 `m0.outbox`，实际知识表及完整录入流程留到 M1、M2。

复现：数据库在线后，执行 `npm run db:migrate` 和 `npm run verify:workflow`。每次使用新运行 ID，不覆盖已有运行记录。

复现：本机安装 Google Chrome、数据库迁移完成后，执行 `npm run test:e2e`。测试拥有专用的 API 3199 与前端 5199 端口，不复用其他项目的服务。

## 验证三 Leiden 计算接口

**结果：通过。**

本机 Python 3.11.16、igraph 0.11.9。Node 侧未来可调用受控 Python 子进程；当前验证以独立 Python 子进程实际读写 JSON，输入包含 schemaVersion、inputVersion、节点 ID、加权边、分辨率和随机种子，输出包含云团成员及孤立节点。

| 场景                               | 观察结果                           |
| ---------------------------------- | ---------------------------------- |
| 三组各 10 个稠密节点，组间弱连接   | 识别为三个 10 节点群组             |
| 额外 1 个孤立点                    | 保留为独立群组并列入 isolatedNodes |
| 相同输入与固定种子重复计算         | 输出完全相同                       |
| 空库与单节点无边图                 | 正确返回空结果或独立节点           |
| 不支持的协议版本、无效端点、负权重 | 返回错误 JSON 与退出码 2           |

验证过程中发现无边单节点不适合交给无限迭代收敛循环，已改为无边图直接生成单节点群组，并对一般 Leiden 计算设置有限迭代次数。此处的三组结果来自人工合成加权图，不代表真实知识语义聚类质量已完成验收。

复现：安装带哈希的 Python 依赖后，执行 `npm run verify:cluster`。结果在本机 `artifacts/clustering.json`。
